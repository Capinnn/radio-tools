# Broadcast Toolkit — Shared JSON Formats

These formats are the contract between the `broadcast` toolkit and the
`studio` player app.  The studio app reads/writes the same files so the
two packages stay in sync without code dependencies.

---

## 1. Rotation file  (`rotation.json`)

A rotation file defines *what* gets played and *how often*.  It is a flat
JSON object with three top-level keys:

```json
{
  "categories": {
    "A": { "sph": 4, "description": "Current / heavy" },
    "B": { "sph": 3, "description": "Medium" },
    "C": { "sph": 2, "description": "Light" },
    "NEW": { "sph": 1, "description": "New music" }
  },
  "rules": {
    "artist_gap": 2,
    "title_gap": 1,
    "category_gap": 1
  },
  "dayparts": {
    "Morning":   { "weights": { "A": 1.5, "B": 1.0, "C": 0.8, "NEW": 0.5 } },
    "Middrive":  { "weights": { "A": 1.2, "B": 1.0, "C": 1.0, "NEW": 0.8 } },
    "Evening":   { "weights": { "A": 0.8, "B": 1.0, "C": 1.2, "NEW": 1.0 } },
    "Overnight": { "weights": { "A": 0.5, "B": 0.8, "C": 1.5, "NEW": 0.3 } }
  }
}
```

### Field reference

| Key | Type | Description |
|---|---|---|
| `categories` | object | Map of category code → metadata. `sph` = target spins per hour. Optional `description`. |
| `rules.artist_gap` | int | Minimum number of tracks between two plays of the same artist. |
| `rules.title_gap` | int | Minimum tracks between two plays of the same title. |
| `rules.category_gap` | int | Minimum tracks between two consecutive tracks from the *same* category (prevents back-to-back A/A). |
| `dayparts` | object | Map of daypart name → weight overrides. Weights are multipliers on `sph`. A weight of 1.0 means use the base `sph` unchanged. |

### Library index file (`library.json`)

A library index is a flat JSON array of track objects, generated by
`trackcheck` or `playlistgen` when scanning a folder:

```json
[
  {
    "path": "/music/artist - title.mp3",
    "artist": "Artist Name",
    "title": "Song Title",
    "album": "Album Name",
    "category": "A",
    "duration": 234.5,
    "replaygain_track_gain": -6.2
  }
]
```

If `category` is absent the track is treated as uncategorised (it will
only be picked when no category constraint is active).

## 2. Schedule file  (`schedule.json`)

A schedule file defines the weekly program clock — which daypart is
active during which hour on which day.

```json
{
  "dayparts": {
    "Morning":   { "start": "06:00", "end": "10:00", "rotation": "rotation.json" },
    "Middrive":  { "start": "10:00", "end": "15:00", "rotation": "rotation.json" },
    "Evening":   { "start": "15:00", "end": "20:00", "rotation": "rotation.json" },
    "Overnight": { "start": "20:00", "end": "06:00", "rotation": "rotation.json" }
  },
  "grid": {
    "mon": ["Morning", "Morning", "Middrive", "Middrive", "Evening", "Evening", "Overnight", "Overnight"],
    "tue": ["Morning", "Morning", "Middrive", "Middrive", "Evening", "Evening", "Overnight", "Overnight"],
    "wed": ["Morning", "Morning", "Middrive", "Middrive", "Evening", "Evening", "Overnight", "Overnight"],
    "thu": ["Morning", "Morning", "Middrive", "Middrive", "Evening", "Evening", "Overnight", "Overnight"],
    "fri": ["Morning", "Morning", "Middrive", "Middrive", "Evening", "Evening", "Overnight", "Overnight"],
    "sat": ["Overnight", "Overnight", "Morning", "Middrive", "Middrive", "Evening", "Overnight", "Overnight"],
    "sun": ["Overnight", "Overnight", "Morning", "Middrive", "Middrive", "Evening", "Overnight", "Overnight"]
  }
}
```

### Grid layout

The `grid` maps a 3-letter lowercase day code to an array of 8 daypart
names, one per 3-hour block:

| Index | Hours |
|---|---|
| 0 | 00:00 – 03:00 |
| 1 | 03:00 – 06:00 |
| 2 | 06:00 – 09:00 |
| 3 | 09:00 – 12:00 |
| 4 | 12:00 – 15:00 |
| 5 | 15:00 – 18:00 |
| 6 | 18:00 – 21:00 |
| 7 | 21:00 – 24:00 |

Each daypart entry in `dayparts` references a rotation file (relative to
the schedule file or absolute).  A daypart may also include a
`"playlist"` key pointing to a fixed playlist file instead of using
rotation.

## 3. Logbook file  (`logbook.json`)

The logbook is a JSON array of play events, newest last:

```json
[
  {
    "timestamp": "2026-08-21T14:05:32",
    "path": "/music/artist - title.mp3",
    "artist": "Artist Name",
    "title": "Song Title",
    "category": "A",
    "duration": 234.5,
    "source": "playlistgen"
  }
]
```

| Key | Description |
|---|---|
| `timestamp` | Local ISO-8601 without timezone (station clock). |
| `path` | Filesystem path of the played track. |
| `artist` / `title` | Tags at time of play. |
| `category` | Rotation category, or `null`. |
| `duration` | Track length in seconds. |
| `source` | What triggered the play: `playlistgen`, `schedule`, `manual`, `studio`, etc. |

## 4. Playlist output  (`playlist.m3u` + `playlist.json`)

`playlistgen` always emits both an M3U file and a JSON sidecar with
richer metadata.

### M3U

```
#EXTM3U
#EXTINF:234,Artist Name - Song Title
/music/artist - title.mp3
#EXTINF:198,Other Artist - Other Song
/music/other.mp3
```

### JSON sidecar (`playlist.json`)

```json
{
  "generated_at": "2026-08-21T14:00:00",
  "seed": 42,
  "daypart": "Morning",
  "target_duration": 1800,
  "actual_duration": 1798.5,
  "tracks": [
    {
      "position": 1,
      "path": "/music/artist - title.mp3",
      "artist": "Artist Name",
      "title": "Song Title",
      "category": "A",
      "duration": 234.5
    }
  ]
}
```
